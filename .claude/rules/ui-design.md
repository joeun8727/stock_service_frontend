# 13 — UI 디자인 & 스타일링

## 디자인 방향

금융 정보 대시보드. **신뢰감 있고 데이터 가독성이 높은** 톤. 차분한 다크 기반 + 데이터 강조 액센트.

- 정보 밀도는 높되 시각적으로 정돈. 숫자가 주인공.
- 긍정/부정 지표는 색으로 직관적 구분 (단, 색맹 고려해 아이콘/부호 병행).

## 스타일링 규칙 (Tailwind + shadcn/ui)

- **shadcn/ui** 컴포넌트를 기반으로 사용 (`Card`, `Table`, `Tabs`, `Badge`, `Skeleton` 등).
- 색/간격/타이포는 Tailwind 토큰 + CSS 변수로 일관성 유지. 임의 매직값 최소화.
- `cn()` 유틸(`lib/utils.ts`)로 조건부 클래스 병합.
- 다크/라이트 토글은 Phase 1 선택 사항 (기본 다크로 시작 가능).

## 데이터 시각화 규칙

- **재무지표 표** (`StockMetricsTable`): ROE/ROA/ROIC/PER/PBR 등을 표로. 단위·기간 명시.
- **감정 배지** (`SentimentBadge`): sentiment 값 → 색/라벨 매핑
  - `>= 0.3` 긍정(초록), `-0.3 ~ 0.3` 중립(회색), `<= -0.3` 부정(빨강).
  - 색만으로 구분하지 말고 "긍정/중립/부정" 텍스트 + 부호 병행.
- **중요도**: 0~100을 프로그레스/뱃지로. HIGH/MEDIUM/LOW 라벨 동반.
- **섹터 트렌드 차트** (`SectorTrendChart`): Recharts 라인/영역 차트. 뉴스 볼륨·감정 추이.
- 숫자 포맷: 큰 금액은 `$1.2B`, 비율은 `%` 변환, 소수 자릿수 통일 (`lib/utils.ts`의 포맷 함수 사용).

## 컴포넌트 작성

- 재사용 단위로 작게. props 타입 명시.
- 로딩 스켈레톤은 실제 레이아웃과 같은 형태로 (레이아웃 시프트 방지).
- 반응형: 모바일에서도 표가 깨지지 않게 (가로 스크롤 또는 카드형 전환).

## 금지

- 인라인 스타일 남발 금지 (Tailwind 클래스 사용).
- 의미 없는 div 중첩 최소화, 시맨틱 태그 우선.
- 자체 디자인 토큰을 벗어난 임의 색상 난립 금지.

> 새 화면/컴포넌트를 만들 땐 frontend-design 원칙(명확한 톤, 일관된 타이포/색, 의도된 여백)을 따르되, 금융 대시보드 특성상 **가독성과 신뢰감**을 최우선으로.
